# ⛪ Church Management System — Hosting & Production Deployment Guide
**Scale:** 1,000+ Church Members · **Stack:** Laravel 12 · PostgreSQL · PHP 8.3 · Beem Africa SMS

---

## 📌 Executive Summary
For a congregation of **1,000 members**, this application typically handles **20 to 100 concurrent active users** during peak windows (e.g., Sunday services, contribution drives, or right after a bulk SMS announcement is sent).

Because the codebase is built with optimized queries, OPcache, and clean relational database models, it requires modest, affordable infrastructure:
* **Recommended Specs:** 1–2 vCPUs · 2 GB RAM (min) · 25–50 GB NVMe/SSD
* **Estimated Server Cost:** **$5 – $12 per month**

---

## 🏗 System Architecture & Requirements

| Component | Specification | Purpose |
|---|---|---|
| **Web & App Runtime** | PHP 8.2 / 8.3 + Nginx (or PHP built-in with container) | Core Laravel 12 runtime |
| **Database** | PostgreSQL 15+ | Relational data, member records, financial ledgers |
| **Queue & Worker** | Database Queue / Redis (`php artisan queue:work`) | Asynchronous Bulk SMS dispatch via Beem Africa |
| **Storage** | Local Persistent Volume / Cloudflare R2 / AWS S3 | Member avatars, official PDF letters, receipts |
| **SMS Gateway** | Beem Africa API (Basic Auth) | Automated church & department SMS notifications |

## 🚀 Recommended Hosting Solutions

### Option 1: Railway (Fastest — Zero Server Admin)
Your repository already includes [`Dockerfile`](Dockerfile) and [`railway.json`](railway.json), making Railway a turn-key deployment.

#### Deployment Steps:
1. **Push your code to GitHub**:
   ```bash
   git add .
   git commit -m "Ready for production"
   git push origin main
   ```
2. **Create a project in [Railway.app](https://railway.app)**:
   * Select **"Deploy from GitHub repo"** and choose your repository.
3. **Provision PostgreSQL**:
   * Click **+ New** → **Database** → **PostgreSQL**.
   * Link PostgreSQL to your web service (Railway will automatically configure the `DATABASE_URL`).
4. **Attach a Persistent Volume** *(Crucial for Member Avatars & PDFs)*:
   * Go to your service **Settings** → **Volumes** → **Add Volume**.
   * Mount path: `/var/www/html/storage/app/public`
5. **Configure Production Environment Variables** (See [Environment Configuration](#-environment-variables-checklist)).
6. **Set Custom Domain**:
   * Under service **Settings** → **Networking** → **Custom Domain**, add your domain (e.g. `kanisa.eagtkiburugwa.org` or `.co.tz`). Free automatic SSL is issued.

## ⚡ Scaling Best Practices for 1,000+ Members

### 1. Run Queue Workers for Bulk SMS
When broadcasting an announcement or reminder to 1,000 members, executing the requests sequentially in the web thread will cause browser timeouts (HTTP 504).
Run a background queue worker on your server:
```bash
php artisan queue:work --queue=default --sleep=3 --tries=3 --timeout=120
```
*(On Railway, add a second service running this start command; on a VPS, use Supervisor or systemd).*

### 2. File Uploads & Object Storage
Member avatars and PDF letters generated by DomPDF should be preserved across deployments.
* **Option A:** Mount a Persistent Volume at `/var/www/html/storage/app/public`.
* **Option B (Recommended):** Use **Cloudflare R2** (S3 compatible):
  * 10 GB free forever.
  * No egress/bandwidth fees.
  * Simply set `AWS_ENDPOINT`, `AWS_ACCESS_KEY_ID`, and `AWS_SECRET_ACCESS_KEY` in `.env`.

### 3. Automated PostgreSQL Backups
Protect your church financials, offerings, and membership records with daily backups:
```bash
# Automated cron job for VPS
pg_dump -U postgres kanisa_db | gzip > /backups/kanisa_$(date +\%Y\%m\%d).sql.gz
```
On Railway, daily automated backups can be toggled directly in the PostgreSQL plugin tab.

### 4. Production Optimization Commands
Whenever deploying an update, execute these cache optimizations:
```bash
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan optimize
```

To clear them during debugging:
```bash
php artisan optimize:clear
```
